# Паспорт проекта

## Цель

`agentic-rag` — учебный, но инженерно оформленный RAG-проект для портфолио ML/LLM
Engineer. Он должен позволять уверенно объяснить устройство загрузки документов,
поиска, генерации, агента и измерений, а не быть набором ноутбуков или обёрткой над
готовым фреймворком.

Целевой сценарий: пользователь спрашивает о технической документации или статье,
система находит фрагменты источников и возвращает ответ с проверяемыми ссылками на
них. Важнее воспроизводимость и доказательства, чем демонстрационный «умный» ответ.

## Принципы работы

- Двигаться по одному этапу: проблема → варианты → решение → реализация → тесты →
  измерение → документация.
- Не выдавать планы, подмены или непроверенные метрики за работающий результат.
- Оставлять выбор модели и провайдера за интерфейсом; тесты не требуют сети, ключа
  или GPU.
- Хранить канонические данные и происхождение отдельно от производных индексов.
- Измерять retrieval, RAG, агента и инференс раздельно, с версией кода, данных,
  модели, конфигурацией и аппаратным окружением.

## Технологические рамки

| Область | Выбор |
| --- | --- |
| Язык и упаковка | Python 3.12+, `uv`, Hatchling, `src/`-layout |
| Проверки | pytest, Ruff, строгий mypy |
| Метаданные и текст | PostgreSQL + SQLAlchemy/Alembic |
| Векторный поиск | Qdrant за интерфейсом; в будущем допустим pgvector |
| Поиск | Dense baseline, затем BM25, RRF и опциональный reranking |
| LLM | Детерминированная подмена и OpenAI-совместимый HTTP-клиент |
| API | FastAPI, OpenAPI и SSE |
| Агент | LangGraph, типизированные read-only-инструменты и жёсткие бюджеты |
| Наблюдаемость | структурные логи, метрики процесса, опциональный Langfuse |
| Развёртывание | Docker Compose; LLM-сервер остаётся внешней зависимостью |

## Что не является целью

- Микросервисная архитектура до появления измеримой необходимости.
- Обязательная облачная модель, ключи в репозитории или тесты с платными вызовами.
- Оценка качества только через LLM-as-a-judge без ручной проверки и происхождения.
- Заявления о production-ready или общем качестве по маленькому авторскому набору.
- Самостоятельный GPU-инференс без подтверждённых ресурсов и бенчмарка.

## Требования к качеству

Каждый пользовательский ответ с опорой на документы должен сохранять идентичность
источника, ревизии и чанка. Отсутствие достаточных доказательств — допустимая причина
для отказа. Внешние входы валидируются, инструменты агента не изменяют данные, а
дорогие либо блокирующие операции ограничены по времени и конкуренции.

Для резюме допустимы только утверждения, на которые есть ссылка на тест, измерение
или воспроизводимую команду. Малый development-набор полезен для регрессий, но не
является независимой оценкой качества модели.
