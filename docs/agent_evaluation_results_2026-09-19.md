# Результаты проверки агента — 19 сентября 2026

Проверены все 14 сценариев `agent_v1` в двух отдельных прогонах: сначала 3, затем
оставшиеся 11. Код агента, runner, сценарии и корпус между прогонами не менялись;
совпадение соответствующих хешей проверено. Оценку ответов выполнил ассистент по
заранее записанным критериям. Это development-набор, а не независимый тест качества.

## Условия

- Модель: `qwen/qwen3.6-35b-a3b`, reasoning выключен, temperature=0.
- Изолированный корпус из 10 заметок в памяти, настоящий BM25 и каталог снимка.
- Рабочие PostgreSQL/Qdrant не использовались; HTTP API приложения не тестировался.
- На сценарий: до 6 модельных вызовов, 8 предложений инструментов, 180 секунд;
  до 4096 выходных токенов на модельный вызов.
- Общий потолок новых вызовов: 8 для первого прогона, 36 для второго.
- Автоматических повторов HTTP и изменений промпта во время проверки не было.
- Контролируемые сценарии используют явно заданные сбои или сохранённые fixture-
  ответы. Их результаты отделены от обычных задач; воспроизведение не считается
  новым платным вызовом модели.

## Главные проблемы

### Повторный поиск без новых доказательств

В `absent_private_fact` пять исполненных переформулировок вернули один и тот же
фрагмент LoRA без запрошенной личной стоимости. Шестое предложение инструмента
остановлено лимитом модельных вызовов. Сумма не выдумана, но полезного отказа нет.

В `empty_retrieval` исполнены четыре пустых поиска и один запрос каталога.
Следующее предложение поиска упёрлось в лимит. Метаданные каталога не заменили
отсутствующие фрагменты, подтверждающие техническое объяснение.

### Хрупкий формат отказа

В `catalog_unavailable` исполнены две неудачные попытки каталога с одинаковыми
нормализованными аргументами, затем три поиска. На шестом модельном ходе появился
обоснованный отказ с объяснением перед `INSUFFICIENT_EVIDENCE`.

Код распознаёт только точное совпадение с этим маркером. Поэтому ответ попал в
проверку цитат и получил `invalid_citations`; бюджета на исправление уже не было.
Итог — `limit_reached`, хотя модель по смыслу признала отсутствие нужных данных.

### Формальная валидность ссылки не гарантирует хорошую привязку

В `catalog_page` и `malformed_catalog_arguments` данные списка верны, однако
T-маркер относится только к сообщению о наличии следующей страницы. Пункты списка
не имеют явной привязки к наблюдению каталога. Структурный валидатор это пропускает.

В `search_compare` источник утверждает, что LoRA сам по себе не квантует базу.
Модель усилила это до категорического утверждения о хранении в исходной точности.
Это отмечено как недостаток поддержки утверждения источником.

## Что сработало

- Арифметика и последовательность «каталог → калькулятор».
- Исправление ложной предпосылки и поиск подтверждающих фрагментов.
- Реальное восстановление после повреждённого JSON аргументов с сохранением ошибки.
- Однократное исправление цитат в полном каталоге и в контролируемом сценарии.
- Ограничители ресурсов: петли завершились без бесконечного исполнения.
- Runner сохранил происхождение ответов, наблюдения, usage и отчёты для проверки.

Средние оценки по шкале 0–2; в скобках — число применимых сценариев.
Неприменимые измерения не считаются нулём или успехом.

успешно справился с отказами. Независимая человеческая оценка не проводилась.

## Следующий шаг

Приоритет — ограничить поиск без новых доказательств и сохранить бюджет на
корректный финальный ответ или отказ. Отдельно устранить зависимость распознавания
отказа от единственного точного текстового маркера.

Изменения ещё не реализованы. Сначала нужны код и локальные проверки, затем
сравнение с сохранёнными проблемными сценариями. Увеличение лимитов или добавление
слепых повторов не решает обнаруженную проблему.
